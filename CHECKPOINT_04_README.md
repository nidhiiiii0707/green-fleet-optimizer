## REAL / DERIVED / SCENARIO_INPUT status
Every decision variable, constraint, and objective is tagged in the CSVs above. Summary:
- REAL: vessel speed bounds, route port coordinates/pairs, fuel-type categories.
- DERIVED: route distance/voyage time (haversine), vessel cargo capacity (mean cargo / load ratio).
- SCENARIO_INPUT: fuel price, GHG emission factor, vessel-fuel compatibility, port fuel availability,
  voyage deadline multiplier, per-route cargo demand assignment.
- UNAVAILABLE (never fabricated): draft-vs-port-depth, port throughput capacity — no physical
  port depth (metres) or rated port capacity exists anywhere in the processed data.

## Environment fix
`models/fuel_xgb_pipeline.joblib` fails to load under xgboost 3.4.1 (`XGBoostError: input
stream corrupted`) but loads and predicts correctly under xgboost 3.0.0 (also 3.1.0, 2.1.4).
This is a version-compatibility issue in the LOADING environment, not file corruption (verified
byte-identical / same MD5 against the sibling project's copy). `requirements.txt` pins
`xgboost==3.0.0`. Working interpreter: `.venv2` in this repo (`./.venv2/Scripts/python.exe`
on Windows), created because the pre-existing `.venv` had broken python3.14 symlinks.

## Caveat (repeated throughout)
The XGB target `Consumer_Total_MomentaryFuel` is a documented INSTANTANEOUS RATE (see
`analysis/02_feature_audit.csv`), and its physical unit is undocumented; the raw telemetry has
no timestamp column, so converting to a voyage total requires a SCENARIO_INPUT sampling-interval
assumption. Fuel price and GHG emission factors are also SCENARIO_INPUT. Absolute Cost/GHG
values here are therefore NOT verified real-world accurate -- only relative comparisons between
candidates under the same fixed assumptions are meaningful.
